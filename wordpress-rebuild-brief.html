JSG CMS rebuilds an agency from facts (NAP, team, catalog coverages, catalog carriers) plus global templates. It does not clone WordPress HTML, Avada, or carrier-slider PNGs. The scrape agent’s job is to fill Onboard Buddy’s payload, not to paste pages.

Grades used in this brief

  • Good — onboard-client (or an existing dashboard API) does this today if the agent follows the contract.
  • OK — works with a second session-auth step, a workaround, or a known parser quirk. Fine for a reviewable staging tenant.
  • Bad — no import path on main today. Park in the scrape bundle. Do not promise it in a client demo or DNS cutover.
  • Landmine — import still returns ok: true while the data is missing. Looks like success; it is not.

1 · Tenant identity Good Landmine

Import: POST /api/onboard-client/ with x-api-key: $ONBOARD_API_KEY (trailing slash required). Body is v2: nested agencyInfo. Slug = slugify(clientName) unless slug is set. Domain = host of business_website, www. stripped. Always skipBuild; status stays onboarding. You do not send skipBuild in JSON — the route hardcodes it.

Landmine: Staging already has Steve White as barry-white-insurance. A POST with clientName “Steve White Insurance” creates steve-white-insurance and may placeholder the domain to *.onboarding.invalid.

Fix: Pilot payload sets "slug": "barry-white-insurance". First greenfield agency omits slug. First POST is staging CMS, never production.

2 · NAP Good

Import: business_name, business_phone, primary_contact_email (must look like an email), business_address + city / zip_code / seo_state. Required to stand up: name, phone, street, city, state, zip.

Landmine: Footer NAP ≠ JSON-LD. Cloudflare email obfuscation. primary_contact_email also creates a client-role CMS login.

Fix: JSON-LD wins on drift; flag the other. Use a real agency inbox, not a personal Gmail, unless you want that login.

3 · Hours OK

Import: business_hours free text. Parser handles Monday - Friday | 9:00am - 5:00pm and en-dashes. Raw string always stored in extras even if parse fails.

Fix: Prefer the pipe format in the payload. “By appointment” / “24/7” will not become structured hours — keep raw for humans.

4 · Coverages OK Landmine

Import today: top-level coverages[] with coverage_key equal to a catalog keyword (car_insurance, not “Auto”). Matcher slug-normalizes only; it does not read alternativeKeyword. Matches → intake cards + Content Schedule + product-page drafts in Review Queue. Unmatched → reported, no card, no page. createIfMissing is ignored on main. high_priority only sorts, then is dropped — put featured keys first in the array.

5 · Carriers Good

Import: comma keys in carriers_selected (progressive,the_hartford) plus free-text list_carriers. Catalog (~206) supplies official name, logo, URL. Unmatched stay name-only — never dropped, never given another carrier’s logo. Do not upload slider PNGs.

Fix: Normalize “The Hartford” → the_hartford. Regionals go in list_carriers.

6 · Team + authors OK

Import: teamMembers[] with stable portalTeamMemberId, name, title (becomes role), bio, email. Invalid email is dropped; member still created. Empty roster falls back to Primary Contact with no photo. Authors collection gets the same people (not NPN/licenses/designations).

Landmine: WP /users are often JSG staff (felix, Nik), not the agency. Phone and credentials on team are not mapped on v2.

Fix: Team page / About only. Park NPN and state licenses in bundle.authors[] for a human in the Authors tab. Production go-live may still want those filled.

7 · Logo + headshots Landmine

Import: CMS fetches media.logo.signedUrl and team headshots (field name is leftover from Supabase; a normal https WP URL is fine). Magic-byte + EXIF strip → R2. Bind by portalTeamMemberId.

Why it fails while ok: true: host must be on PORTAL_ASSET_ALLOWED_HOSTS; https only; redirect: 'error' (http→https and www↔apex skip the file); ≤10MB; 15s. Contract text still talks about Supabase. WP almost always 301s.

Fix: Agent follows redirects itself, sends the final URL, allowlists every final host (apex, www, i0.wp.com, Gravatar) before POST. Fallback: session POST /api/dashboard/media with bytes (8MB, bypasses allowlist) then PATCH business.logo.

8 · Hero / about photos OK

Import: v2 does not set heroImage or about.image. Park URLs in the bundle. After tenant exists: session media POST, then intake PATCH heroImage (that path is in Agency Info). About image may need a human in Who We Are — it is not the same branding field.

Landmine: Upload alone does not show on the homepage. Do not drop agencyInfo to “use v1” for hero — you lose v2 coverages/media.

9 · Locations OK Landmine

Import: Primary office is Agency Address, prepended at bake (WO-254). Additional offices only: address_N / city_N / state_N / zip_N / phone_N for N=2…6. Structured NAP required. If local phone is missing, HQ phone is used (the agent plan was wrong to say the row is always skipped). Country is forced US. geo is not mapped on v2.

Landmine: Putting HQ in both address.* and locations[] → two map pins. “Cities we serve” landing pages are not offices.

Fix: Physical street NAP only. City pages go to URL inventory. More than five extras → unmapped.

10 · Fonts + colors OK

Import: Not onboard-client. Onboard Buddy only stores flags like use_existing_website_colors in extras. After tenant id exists, session PATCH /api/dashboard/tenants/:id/theme. That PATCH replaces the token map — send every token you care about in one call.

11–12 · Social, GBP, reviews Good / OK

Socials need full https:// or they never become socialLinks. GBP listing → platform: google. Reviews widgets on WP are ignored. After import, session POST …/reviews/refresh reads that Google URL and drafts Google reviews (worker + aggregator keys). Manual refresh never auto-publishes.

13 · Forms + quoting Good

Onboard provisions five standard forms (contact, servicing, business-insurance, personal-insurance, blog) with First/Last/Phone/Email/Message. It does not import WS Form, Gravity, CF7, WPForms, or HubSpot. Quote iframes → quoting_tool_1. Client login URLs → client_portal_1. Extra WP forms stay in unmapped.

14 · Tracking OK

Session tracking POST. Allowed hosts: Google (GA4/GTM/Ads), Meta, Microsoft Clarity/Bing, Cloudflare. CallRail, HubSpot, LiveChat, Hotjar → rejected. Park those. Phone tracking is a cutover checklist, not an import.

15 · Sitemap / URL inventory Bad

Every leftover WP URL goes in urlInventory with triage keep | rewrite | consolidate | retire, plus a guessed CMS page type when known. Nothing in that list becomes a CMS page automatically. Standard sitemap (Home, About, Contact, Team, …) is provisioned empty/generated. Product URLs become coverage drafts only when the catalog key matched.

A 500-URL XML sitemap is a triage job, not an import job. City service pages and thin listicles should be retire/consolidate, not 80 extra product jobs.

16 · URL redirects Bad on main

Park { source, target, status: "301"|"410" } with source as a path (/auto-insurance/), not an absolute URL. This git branch has POST /api/dashboard/tenants/:id/redirects op=import (session, skipBuild). Main/prod may not. Targets must match live path rules (on this branch, national products are hierarchical; blogs are /learning-center/{slug}/). Do not guess /products/auto-insurance/.

Do not DNS-cut until redirects exist on the env you are cutting. That is how the old book 404s.

17 · Blog posts Bad

blogs/generate + push creates new blogPost pages from a keyword in agency-grounded Grok voice. It will not ingest WP body, date, or Yoast. Using it for ranked URLs replaces equity with different copy. Until an ingest exists: scrape title/date/excerpt/URL for inventory; skip thin/spam; do not paste Avada HTML; author is the agency person, not JSG WP users.

18 · Legal Bad

Privacy and Terms on the CMS are generated drafts, not the agency attorney’s PDF. Park WP legal URLs. A human pastes or uploads before go-live if counsel cares (they will).

19 · Licences / production gate OK

v2 does map npn and year_founded (the agent plan was wrong to park those). licenceNumbers and legal name are still unmapped. Production enqueue can fail the org-credentials gate without founding year / NPN / licences even if staging “looks done.”

20 · Staging preview OK

Onboard enqueues a staging build (not production). A second staging build can fire after coverage jobs finish. Staging may include pending_review and empty-body routes so the frame is not a pile of 404s. If worker/Redis are down, drafts never appear and staging stays empty. That is operational, not a scrape bug.

If you only read one conceptual tab, read this: onboard-client is the same door Onboard Buddy already uses. WordPress is a scrape in front of that door, not a second CMS importer.

Two pipelines, on purpose

Onboard Buddy is for new clients filling a portal. WordPress migration is a crawl + triage + the same onboard POST for facts. URL inventory, blogs, and redirects stay out of onboard-client (Factory: do not overload it). Mixing them is how you get 80 junk product pages and no 301s.

What “imported” means here

Templates are global. Only content and tokens vary. The scrape fills intake JSON; the render pipeline is a pure function of that content. Generated product/about copy is grounded in intake and lands in the Review Queue. A human still publishes. That is invariant I5, not a temporary gap.

Auth split

ONBOARD_API_KEY opens only /api/onboard-client/. Theme, media upload, tracking, reviews refresh, intake PATCH, redirect import use a logged-in dashboard session (grok@jumpsuitgroup.com on the shared machine). The scrape agent should stop at the bundle + onboard POST.

The honest caveat

This will produce a JSG site that is true to the agency’s facts, not a pixel clone of WordPress. If the team’s success bar is “looks like the old theme with the old blog HTML and the old URLs on day one,” this plan is the wrong plan. If the bar is “staging tenant we can review, then generate and 301,” it is the right one — and the landmines are process, not architecture.

Can the agent push like Onboard Buddy?

Yes, for agency facts. Same endpoint, same v2 JSON shape, same skipBuild. No, not for the whole WordPress site (HTML, Yoast per URL, blogs, tracking, redirects).

Why not one mega JSON into onboard-client?

Onboard Buddy is new-client intake. A migrate also needs a redirect map and URL triage. Stuffing that into onboard-client mixes pipelines and skips the human URL review. Factory already recorded that split.

Why not copy the WP pages?

Structure is global (invariant). Copied Avada HTML would be a one-off template. Coverage pages are generated from the catalog so every tenant stays on the same components. Boilerplate “10 tips” posts were an SEO liability on the old sites anyway.

Why skip carrier PNGs?

The Carrier Catalog already has official logos. Scraped slider files are inconsistent, often watermarked or outdated, and would fight catalog enrichment at bake.

Is Instinctive Matching required to start?

No. The agent synonym table unblocks a pilot. ICM is required before we scale to agencies whose nav is all “Auto / Home / Comp” without a human mapping pass. Create If Missing is required before niche products (Laser Tag) should appear as pages. Both are written in Factory; neither is on main yet.

What does “done” look like for this brief?

Team agrees the grades. Pilot rules (slug, staging, no DNS) are written. CoS is empowered to block POST on missing catalog keys or unresolved image hosts. First staging tenant is allowed. Cutover is a separate green light after redirects.

What does “done” look like for a rebuilt client?

Staging: NAP complete, team + logo visible, featured coverages in Review Queue, carriers with catalog logos, theme tokens applied, staging URL loadable. Production: human-approved pages, licences/NPN/founding year, redirect map applied, tracking leftovers handled, DNS. That last sentence is not this sprint.
