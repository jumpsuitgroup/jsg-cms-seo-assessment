The inversion

The competitive audit’s governing principle is structural quality automatic, content uniqueness mandatory. JSG CMS already won the old WordPress failure modes (static export, CountUp SSR, NAP, authors, llms.txt, staging noindex). It did not invert uniqueness: AC-CGE-006.3 explicitly forbade cross-client similarity checks. Starter libraries across N tenants are scaled-content risk. Prompt context does not catch a city-swapped paragraph.

Why uniqueness is last

Comparing onboard of N tenants × ~40 coverage pages pairwise on the publish click would stall Review Queue and false-positive on legal boilerplate and shared starters. Shadow mode needs Answer Summary, hierarchical URLs, Location pages, Template Stubs, and sourced stats to exist, or the scores are noise. Enforce stays off until those scores are believed.

Why is uniqueness 296 before 295 even though 295 is the lower number?

Factory numbers are extract order, not run order. Shadow index (296) must exist before enforce (295) can consult it. The X.Y column on Workstreams is the run order.

Why not comparison-only uniqueness?

Generation would still converge on starter language. Keep context-driven uniqueness (CGE) and add publish-time comparison as a second line. Stack them; don’t replace one with the other.

Why hierarchical URLs now if we used to wait on redirects?

Waiting was to avoid mixed taxonomies on live URLs. Nothing is live, so hierarchy can ship without recreating that failure. Path changes after publish still write 301s. WordPress cutover still needs a Migration Redirect Map (WO-298).
